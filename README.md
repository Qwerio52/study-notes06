# study-notes06

##### \## 第七章 文件和数据格式化 学习心得

> 知识点：文件打开与读写、文件编码、一维/二维数据格式化、CSV读写、wordcloud词云可视化



本章实现了数据从内存到本地持久存储的跨越，打通了外部文件读取、数据格式化、结果可视化的完整链路。



1\. 文件基础操作：掌握 `open()` 函数与不同打开模式 `r/w/a/r+` 的区别，理解编码参数对中文文件的重要性，编码错误是中文文本处理高频报错点。优先使用 `with open()` 上下文管理器，它能够自动关闭文件，避免忘记 `close()` 造成文件资源占用。逐行遍历文件适合处理大文件，不需要一次性加载全部文本，降低内存占用。



2\. 一维与二维数据格式化：一维数据一般由列表、集合表示，常采用空格、逗号分隔存储；二维数据是多行多列的表格结构，用嵌套列表表达，典型存储格式为CSV。一维、二维数据的读写思路清晰，CSV作为轻量表格格式，不需要数据库支持，读写简单，适合小型结构化数据。我认识到，数据的组织维度决定了存储方案，合适的数据格式可以简化后续处理逻辑。



3\. WordCloud词云综合案例：词云项目是第六章知识与本章内容的结合。完整流程：读取本地文本文件 → jieba分词、过滤停用词 → 统计词语频次 → 调用wordcloud生成可视化图片。串联了文件读写、字典词频统计、第三方库调用，是一个综合性小项目。



4\. 整体感悟：前面章节操作的数据都存放在内存中，程序结束数据就丢失；学习本章之后，可以把运算结果保存到本地文件，也能读取外部文件作为程序输入。工程上常见流水线：读取文件 → 清洗处理数据 → 格式化保存 / 可视化输出。本章也熟悉了第三方库的使用方式，为后续数据分析、可视化学习铺垫基础。



\### 本章重点小结

\- 文件：`with open()` 自动管理上下文；注意编码，防止中文乱码

\- 一维数据：线性序列，分隔符文本存储

\- 二维数据：表格结构，优先使用CSV格式

\- WordCloud：文本词频可视化，依赖分词预处理
